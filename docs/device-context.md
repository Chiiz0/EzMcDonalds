# 设备字段的来源与独立实现范围

“已有设备上下文”是当前适配器采用的输入来源，不是“技术上永远无法独立实现”的结论。当前优先支持已经接入的用户；空白机器首次授权暂缓。

| 输入 | 当前已核对的来源 | 项目可以做什么 | 尚未证明的部分 |
|---|---|---|---|
| `token` / `deviceToken` | 已支持的官方客户端通过 `MCDDeviceUtils.deviceUDID` 获取本地安装标识，缺失时由 `OpenUDID.value` 生成并保存 | 可以实现持久化的本地安装标识生成 | 新标识与其他字段一起能否通过实际登录、是否需要额外初始化 |
| `d` / `riskDeviceId` | 请求构造调用 `SmAntiFraud.getDeviceId`，属于数美 SDK 输出 | 当前读取用户已授权的官方设备结果 | 独立初始化的完整协议、环境依赖和服务端接受条件 |
| v4 请求签名、登录字段加密 | 固定构建中的算法与配置 | 已实现本地计算，已与成功官方请求对照 | 不同构建、其他平台协议兼容性 |
| v5 请求签名 | 签名计算外还包含设备与环境运行字段 | 已实现编码计算，输入来自用户授权样本 | 独立采集这些运行字段、长期更新，以及跨会话绑定规则 |
| `sid`、`refreshToken` | 登录或刷新接口成功响应 | 保存、核验、按需刷新 | 服务端有效期不作自行假定，刷新不能替代设备初始化 |

数美的[官方 iOS 接入文档](https://help.ishumei.com/docs/tw/sdk/iOS/developDoc/)说明：SDK 初始化采集设备信息并联网，缓存服务端下发的标识；业务事件通过 `getDeviceId` 获取结果。它还区分会变化的 `boxId` 与 `boxData`。因此，生成格式相同的字符串不等于完成设备初始化。这份通用 SDK 文档不证明麦当劳当前服务端具体采用哪些检查。

本机安装的“Mac 客户端”在 `Info.plist` 中声明 `iPhoneOS`，不是已经验证可直接作为 macOS 命令行库加载的 SDK。研究轻量本地辅助程序是一个方向，但仍需验证 SDK 对宿主、系统 API、应用配置和网络初始化的依赖。安卓实现也必须独立核对，不能仅修改平台请求头并沿用 iOS 运行字段。

当前短信证据只证明：此前缺少 SDK 设备字段的请求被拒绝；随后同时换用本人官方 `token` 与 `d`，脚本发送短信、登录和钱包核验成功。没有做单变量实验，不能断定某一个字段是唯一原因，也不能据此断言独立实现不可行。

最初的 v5“同会话、24 小时”规则是本项目的保守限制，不是已确认的官方有效期。现在增加显式的同设备上下文只读验证路径，仍保留 24 小时采样期限。会话刷新不会人为延长运行样本时间，也不把未知的环境字段设成默认“正常”值。下一步研究应分别验证字段生成、实际初始化和服务端接受情况，保留真实来源与时效。

## 同设备上下文、不同会话的只读对照

对两个用户自己授权的账号，先核对 `deviceToken`、数美 `d`、客户端类型/版本/语言及二进制构建一致；保留目标账号自己的全部登录字段，只在内存中采用来源账号的近期 v5 运行字段。目标账号的 `GET /bff/order/orders` 使用新 v5 签名后返回 HTTP 200、成功标志及有效列表；同一路由的坏校验位对照返回 HTTP 401。

这次 GET 对照只证明新的目标会话通过了只读校验。后续另经用户明确授权，该目标账号使用相同运行证据，通过公开核心的 MCP 完成一笔真实订单 POST 与麦钱包付款；订单、收银台和余额差额一致。仍未验证跨设备或超过 24 小时的样本。CLI `account runtime TARGET --device-from SOURCE` 本身只做只读核验；失败不修改账号，成功不改变原始采样时间，也不提高消费额度。直接导入文件仍要求同会话；短信登录和会话刷新不会自动复制其他账号的运行字段。

a18 起，同一会员重新登录或刷新时，可将仍近期、完整匹配设备上下文的本人样本保存为待核验资料。`account runtime TARGET --previous-device` / MCP `account_runtime_restore` 使用当前会话做固定 GET 验证后恢复，不再要求从其他账号或文件找回同一份资料。它没有实现设备字段生成或跨日续期，详见[会话维护](session-maintenance.md#恢复近期的本人设备样本)。

已支持客户端的内置 `requestConfig101.json` 将 v5 签名规则配置为 `POST /bff/order/orders`。原生选择逻辑优先读取运行配置，缺失时才使用内置配置，因此不能把内置规则当成线上配置的保证，也不能据此提供一个已验证的只读官方采样入口。目前仍需要用户自己的授权样本或请求侧断点；没有实现“随便打开一个页面即可更新运行字段”。


## 无订单取得官方运行证据

本机采样核心已在官方 App 成功取得余额请求与同会话 v5 订单请求头；后者在请求头阶段被终止，没有发送至上游。导入前完整重建签名，随后用新计算签名执行固定订单列表 GET 成功；独立核对订单列表、原单支付状态及钱包余额未变化。项目现在提供 [sampling-capture](guarded-capture.md) 封装证书复用、请求阻断和代理恢复，仍需人在 App 操作。此证据不等于独立生成设备字段，也未证明超过24小时或跨日无人值守。

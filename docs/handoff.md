# 维护交接

交接日期：2026-11-12。原持续开发目标已由用户停止；这次提交用于交接，不表示整体产品目标已经完成，也不启动新的采样、下单或付款。

## 从哪里接手

1. 阅读根目录 [README](../README.md) 的安装、本人授权、报价和付款流程。
2. 按下方命令完成干净 checkout 的离线测试与构建，区分核心与实验。
3. 当前主要开发卡点是**不创建测试订单地取得并导入新运行字段**；直接看[实验说明及代码地图](../experiments/readonly_runtime/README.md)。
4. 需要真实账号或消费验收时，由账号所有者重新确认范围。历史单次购买授权已经使用，交接不转移授权。

正式包版本保持 `0.1.0a50`，38个 stdio MCP 工具。入口为 `src/ezmcd/cli.py` 与 `src/ezmcd/mcp_server.py`；账户、消费策略、购买日志和幂等状态由本地存储管理。实验源码已提交至 `experiments/readonly_runtime`，但不进入 wheel/sdist，也未接入正式命令或 MCP。

## 最新实验交接

- 当前原型是正向匹配麦当劳进程的采样，固定 `api.mcd.cn` 与 `img.mcd.cn`，不写系统代理；配置变化仅在本机响应里加入精确钱包 GET 签名规则。
- 已观察到4个 v5 钱包 GET，但当时只记录了上下文不匹配的笼统错误；原始头没有保存为可导入样本。不能猜测具体差异，也不能声称已有新凭据。
- 新代码在错误中只输出字段名，并在第一次上下文拒绝后立即转入恢复。新诊断尚无新的实机采样结果。
- App 会持久保存签名配置。恢复要实际看到未改动配置之后的同会员有效 v4 钱包请求；退出代理、看到余额或测试通过都不能单独代替恢复证据。
- 配置恢复和凭据导入分开判断：同会员自己的会话变化不应阻止配置恢复；导入仍严格核对两阶段上下文，保留原策略、偏好、购买历史和观察时间。
- App 曾显示查询失败，重新登录后正常；尚未找到统一根因。自动退出 App 曾被误认为闪退，现明确输出阶段结束原因与退出信号数量。应核对真正运行的转置 App 路径；账户页面异步加载会改变钱包按钮位置。
- 交接时保留已有账号和原付款记录，没有待执行的购买授权。三份实验记录均已验证恢复，原采样子进程已结束、临时叶证书私钥已清理、系统代理关闭；持久域名证书按用户此前授权保留。后续证书撤销由本机用户决定，不随提交自动删除。

## 干净 checkout 验证

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -e . build
.venv/bin/python -m unittest discover -s tests
.venv/bin/python -m unittest discover -s experiments/readonly_runtime -p 'test_*.py'
.venv/bin/ezmcd --data-dir .private/demo demo --run
.venv/bin/python -m build
```

核心测试在无私有证据的 checkout 中会跳过相应本机对照项；实验测试全部使用合成数据。CI 在 Ubuntu/macOS × Python 3.11/3.14 上运行测试与构建，不持有真实账号，也不安装系统证书或执行购买。

本次交接的干净副本已在 macOS / Python 3.14 通过772项核心测试（2项跳过）、70项实验测试、模拟演示和 wheel/sdist 构建；正式与实验源码的测试结果应分开记录。远端结果以本次提交对应的 CI 为准。

正式版本号未变化；交接代码应以 Git 提交 SHA 和对应四组合 CI 为准。检查构建产物中不含 `experiments`、私有资料或官方二进制，避免把“源码可读”变成默认安装的能力。

## 下一位维护者的验收顺序

1. 先定位真实 v5 上下文差异，不降低身份/签名校验，不伪造 SDK 字段，不改采样时间。
2. 在明确授权的本人环境完成一次 v5 钱包样本、独立恢复、清理、固定只读核验和原子导入；再验证重复导入与异常中断。对比原策略、偏好、购买日志及样本日期。
3. 核验客户端会话变化、采样启动竞态、子进程退出与证书撤销；实验 CA 实现目前是独立副本，正式集成前需要整理。
4. 在拥有新证据后，由用户另行确认具体门店、商品、日期/时区、取餐方式、新鲜优惠报价、预算和仅一单范围，验收真实下单/付款及原键重复查询。没有新授权就只做非消费检查。
5. 补齐普通券/更多商品、跨日维护和空白环境安装证据，再决定正式发布和是否实现持续授权下的日常自动化。不得把单次付款成功升级为长期全自动可用。

交接完成只指源码、文档、检查与远端同步完成；上述未验收项仍属于后续开发工作。

# 能力与证据

“参数化实现”“模拟通过”和“真实支付验收”是不同状态。`capabilities`工具返回相同边界。

| 能力 | 当前状态 | 证据与限制 |
|---|---|---|
| Python包、CLI、stdio MCP | 已实现并测试 | 安装、进程握手、35个工具发现、模拟全流程 |
| 多账号身份和凭据隔离 | 实现，隔离测试通过 | 原接入账号与新短信账号独立保存、只读核验；多账号真实购买未验收 |
| 用户手机号授权 | 官方App登录后本地 HAR / 单请求采样导入 | 校验签名、实时检查；支持更新与本地撤销。手机号仅可选脱敏标签；项目不声称验证了号码归属 |
| 手机验证码登录 | 本地 CLI 真实验收 | 已注册账号，依赖本人已有官方设备上下文；短信、登录、钱包核验和保存通过；MCP不接收手机号或验证码 |
| 空白设备初始化与登录安全挑战 | 未实现 | 缺设备字段发送前停止；官方验证交回官方入口，不生成 SDK 验证结果 |
| 已有账号会话刷新 | CLI / MCP 已实现、真实核验通过 | 持久化刷新记录与候选会话；重复调用不重复刷新；跨日运行待验收 |
| 运行字段独立更新与显式复用 | CLI 已实现，同设备 v5 GET 和一笔新会话下单付款通过 | 保留真实采样时间、登录和消费日志；跨设备与跨日有效性未验证 |
| 历史运行字段诊断 | CLI / MCP 已实现，当前样本真实 GET 通过 | 超过24小时的检查限制有离线测试；不延长样本期限，不授权下单 |
| 请求头私有终端导入 | 已实现并测试 | 无需保存原始采样文件；请求侧断点操作指引已提供，隐蔽粘贴入口本身尚未新增实操验收 |
| 单请求文本/剪贴板接入 | CLI 已实现，文本入口真实余额核验通过 | cURL/原始 HTTP 仅解析不执行；签名校验、原文不落盘、同账号更新保留日志；官方 App 新复制与剪贴板实操待验收 |
| 无订单运行字段采样 | 本机 sampling-capture；核心实机验收通过 | 受限证书复用、120秒窗口、发送前阻断订单、App 退出后恢复代理；仍需人工操作 App，新增样本只读验证通过，无新增消费 |
| 下单运行字段自动更新 | 未实现 | 当前v5运行字段24小时过期即停止；该期限为项目限制 |
| 门店选择 | 任意七位代码参数 | 仍须提供用户选择的取餐柜或柜台自取；两种门店的准备与报价有实测 |
| 实际取餐方式查询 | pickup_methods，真实 MCP 查询通过 | 初始确认页区分可用、默认已选和支持；不等同于已准备报价中的选择 |
| 显式取餐方式选择及报价恢复 | checkout_quote_pickup / status，柜台自取真实报价通过 | 保存一次切换回执与120秒报价；重启或重复调用不重发；提交前只读核对完整购物车及价格。得来速仍未适配 |
| 柜台自取订单与付款 | 参数化实现、模拟全流程通过；真实付款未验收 | 订单须符合到店外带、非取餐柜及无得来速状态等字段；不把一次真实报价当作消费验收 |
| 门店发现 | 城市/店名搜索、明确坐标附近查询、分页与收藏 | 城市名解析、原店关键词及附近店已真实只读核验；不擅自获取位置 |
| 偏好与实时选餐方案 | 本地保存及只读 meal_plan | 原早餐偏好真实解析成功；可记住指定券名称、配料保留/去除及免费单选，缺货、歧义、约束冲突、时段和价格问题停止 |
| 账号诊断与凭据指引 | doctor / account_diagnose / 本地指南 | 区分会话过期、设备字段、运行样本、策略；凭据留在本机 |
| 权益卡与券概况 | 真实只读核验 | 显示卡有效期与券分类数量；不代表所有券均已支持兑换 |
| 时段及完整分类菜单 | 实现、真实只读验证 | 新MCP实际读出原店87个菜单条目，含嵌套分类 |
| 新增普通单品购物车 | 多份、多品加购与报价真实通过 | 两份脆薯饼、脆薯饼＋脆香油条各¥17.00并清空；另一门店加购通过但取餐方式不兼容，未购买 |
| 清空并重新选餐 | MCP 实现并真实验证 | 新鲜引用、内容比对、发送前日志、重复只查询；不取消订单，不提供跨客户端原子锁 |
| 加购丢响应与重启恢复 | 本地草稿日志、CLI/MCP，真实车上的本地故障注入通过 | 找回指定或最新请求，完整内容匹配后再报价；不重建草稿、不换键补加；旧版记录不可猜测恢复 |
| 已过取餐时间的意图恢复 | 本地列表与明确结束，隔离测试和 MCP 重启通过 | 只结束未解决的加购/取餐准备，保留写入占位；不清车或改购买。实际账号离线列表核对未改日志；跨日凭据维护另行验收 |
| 套餐组件选择 | 详情、构造与约束测试通过，原组合真实加购报价通过 | 显式选择每轮组件，普通单品和type=7套餐；更多组合仍待验收 |
| 免费保留/去除及单选配料 | 实现，少冰真实加购与报价通过 | 识别选项及单品确认页回显；售罄无默认组不提交，更多配料待验收 |
| 商品规格聚合页 | 实现、原组合真实只读核验通过 | 展示规格及当前菜单中可继续选择的单品/套餐，不借用聚合页优惠 ID |
| 高级自定义规格 | 尚未全部实现 | 收费配料、其他冰量结构/换奶、未匹配菜单的聚合商品等先在 App 配置，未识别结构停止 |
| 早餐卡优惠 | 公开核心真实加购、报价、付款验收 | 一笔组合优惠 ¥8.40、实付 ¥12.60 |
| 门店时段券及对应商品查询 | 真实只读核验通过 | 原店7张券，5张报告可用；¥9.90冰美式券商品和默认详情可配置，最终资格仍需结算 |
| 普通单品券加购与报价 | 一张冰美式券加少冰真实通过 | 回读确认券和配料，报价¥9.90、优惠¥9.10；普通券付款尚未验收 |
| 特殊券、整单优惠 | 尚未全部支持 | 预付、多商品组合、条件券、零元券及未识别费用/优惠停止，不静默丢弃优惠 |
| 通用下单付款核心 | 参数化实现，MCP 原早餐真实付款通过 | 多商品/数量、门店/日期非固定；其他场景真实消费验收待做 |
| 付款前套餐归属核对 | 实现并隔离测试，原已付订单只读回归通过 | 组件必须属于对应商品及份数，跨套餐交换即使总数相同也拒绝；没有新增消费来测试拒绝路径 |
| 原套餐纯脚本真实付款 | 原型与公开核心分别完成 | 公开核心经 MCP 支付一笔 ¥12.60，订单/收银台/余额一致 |
| 支付密码/风险挑战 | 交回官方入口 | 不通过MCP输入密码，不伪造验证结果 |
| 余额不足时报价 | 已实现并测试 | 可以核对真实金额、优惠和付款缺口；创建订单前再次检查余额 |
| 防重复执行 | 实现、离线测试和真实重启验证通过 | 相同购买请求重启后返回原订单，无新增订单/预支付/消费写入 |

| 自动取消/退款 | 未暴露 | 官方入口处理，保留尝试以防自动重购 |
| 自动购买调度 | 未启用 | 个人Agent可在本地策略内调用 |

不能把限制改成“成功”占位，也不能为让演示通过而关闭价格、优惠、订单身份、签名或去重校验。

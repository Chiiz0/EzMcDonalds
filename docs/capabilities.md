# 能力与证据

“参数化实现”“模拟通过”和“真实支付验收”是不同状态。`capabilities`工具返回相同边界。

| 能力 | 当前状态 | 证据与限制 |
|---|---|---|
| Python包、CLI、stdio MCP | 已实现并测试 | 安装、进程握手、16个工具发现、模拟全流程 |
| 多账号身份和凭据隔离 | 实现，隔离测试通过 | 按官方会员标识绑定；第二个真实账号未验收 |
| 用户手机号授权 | 官方App登录后本地 HAR / 单请求采样导入 | 校验签名、实时检查；支持更新与本地撤销。手机号仅可选脱敏标签；项目不声称验证了号码归属 |
| 手机验证码登录 | 未实现 | 需核对真实登录流程、设备字段及官方验证交互 |
| 会话及运行字段自动刷新 | 未实现 | 当前v5运行字段24小时过期即停止 |
| 门店选择 | 任意七位代码参数 | 仍须支持当时的自取和店内取餐柜；原店实测 |
| 门店发现 | 收藏列表和代码直查 | 地图搜索与附近门店界面尚未完成 |
| 时段及完整分类菜单 | 实现、真实只读验证 | 新MCP实际读出原店87个菜单条目，含嵌套分类 |
| 新增普通单品购物车 | 实现，尚待真实写验收 | 空购物车、无规格和活动的type=1商品 |
| 套餐组件选择 | 详情真实只读验证，构造与约束测试通过 | 显式选择每轮组件，普通单品和type=7套餐；新加购写入待验收 |
| 高级自定义规格 | 尚未全部实现 | 冰量、换奶、多选等先在App配置，未识别结构停止 |
| 早餐卡优惠 | 原型真实验收 | 新核心对相同证据请求正文逐字段匹配 |
| 更多优惠券、整单优惠 | 不保证支持 | 无法解释的费用/优惠会停止，不静默丢弃优惠 |
| 通用下单付款核心 | 参数化实现、模拟通过 | 多商品/数量、门店/日期非固定；其他场景真实消费验收待做 |
| 原套餐纯脚本真实付款 | 已完成 | 原型一笔¥12.60，订单/收银台/余额一致 |
| 支付密码/风险挑战 | 交回官方入口 | 不通过MCP输入密码，不伪造验证结果 |
| 防重复执行 | 实现并测试 | 幂等键、内容指纹、账号锁、服务端已有订单、发送前日志 |
| 超时恢复 | 查询已有结果 | 未知结果不可重新发送；不是服务端恰好一次事务 |
| 自动取消/退款 | 未暴露 | 官方入口处理，保留尝试以防自动重购 |
| 自动购买调度 | 未启用 | 个人Agent可在本地策略内调用 |
| Windows/Linux真实支付 | 未验收 | POSIX核心；真实适配依赖当前macOS官方客户端构建 |
| 公网多租户服务 | 未提供 | stdio进程属于本机用户，无HTTP服务或公网OAuth |

不能把限制改成“成功”占位，也不能为让演示通过而关闭价格、优惠、订单身份、签名或去重校验。

# 取餐柜与柜台自取

`request.eat_type` 支持 `locker-in`（店内取餐柜，默认）和 `take-in-store`（柜台自取）。两者不能自动替换；门店必须实际提供用户选择的方式。堂食、得来速、路边停车取餐及需要车牌的流程仍未适配。偏好文件也可以保存这两个值。

## 选择与报价

使用同一份 request 完成菜单、加购、购物车查看及报价。餐品非空时调用 `pickup_methods` 查看初始确认页，分别核对所需方式是否可用、是否已选中、是否由项目支持。

- 已选中所需方式：直接调用只读 `checkout_quote`。
- 可用但未选中：先 `cart_get`，使用返回的新鲜 `cart_ref` 调用 `checkout_quote_pickup`。该工具发送一次取餐方式切换 PUT，可能影响确认页或购物车，因此不标记为只读。它不创建订单、预支付或扣款。
- 不可用或遇到特殊流程：停止，让用户选择其他方式、门店或官方入口，不静默改成堂食或原价。

```json
{
  "request": {
    "account": "personal",
    "store_code": "1234567",
    "pickup_at": "2026-11-02T10:15:00+08:00",
    "max_amount_cny": "20.00",
    "eat_type": "take-in-store"
  },
  "cart_ref": "cart-<cart_get返回的引用>",
  "idempotency_key": "breakfast-counter-quote-1"
}
```

门店与日期仅为格式示例。返回 `state=READY` 时包含 `quote_id`、餐品、优惠、金额、`pickup_confirmation` 和 `checkout_blockers`。这就是应审阅的报价；无需再调用初始 `checkout_quote`。在已有消费授权和预算内，可将该 `quote_id` 交给 `checkout_submit`。

报价有效期最多120秒，从这次准备开始计时。创建订单前只读重查当前购物车、可用方式和初始确认页，要求商品、配料、券、金额、餐具及取餐时段仍与准备时一致，使用已经核验的目标取餐方式构造订单。不会为重新核对而再发切换 PUT。

## 为什么初始确认页可能仍显示堂食

实际接口的切换返回 `confirmInfo`，其中选中柜台自取；随后重新读取初始确认页仍可能选中默认堂食。官方客户端把切换返回的数据保存在当前页面，而非依赖下一次初始 GET 记住选择。

项目同样保存这次切换回执和对应报价。`pickup_methods` 展示的是**初始确认页**，`READY` 报价内的 `pickup_confirmation` 展示的是**这次已核验的选择**。不能因为初始 GET 仍是默认选项，就重复切换或替换已有报价。

切换响应省略的餐具信息按官方客户端行为保留原选择；门店、时间、方式、商品及价格必须由新的响应完整提供。切换改变了餐品、价格、优惠或餐具时，当前适配器停止并要求核对，不自动接受变化。特殊整单活动、未适配优惠和车牌要求交回官方入口。

## 中断与恢复

调用 `checkout_quote_pickup_status(account, operation_id?)` 找回指定或最新一次准备，无需保存上次聊天或幂等键。重复原 `checkout_quote_pickup` 请求也只检查原记录；更改原请求或购物车引用不能沿用原键。

| state | 含义 |
|---|---|
| `READY` | 已保存切换回执，当前购物车仍匹配，原报价尚有效；审阅报价和授权后才可提交 |
| `UNKNOWN` | 回执缺失、会话不可用、购物车变化或核对失败；查看 error 和 recovery_action，不提交 |
| `EXPIRED` | 原准备已过期；查询不会续期，也不会重发 |

回执已保存而本地报价保存中断时，恢复可以仅用该回执和新的只读检查补齐报价。切换回执彻底丢失时，初始 GET 不能证明原选择，项目不会猜测恢复。

未核验的准备阻止新键准备、新加购和新订单提交。先查询原记录；若用户决定重新选餐，使用原 request 核对并明确清空购物车后再开始新意图。清空不取消已发送的请求。已确认的准备即使过期也保留日志，新报价需要重新查看购物车；不会重用旧键或旧引用。

同一账号有本机锁，但官方 App、其他客户端和本工具之间没有跨客户端原子事务。准备和提交期间不要同时编辑。该记录只保存在本机，不修改偏好、不授权消费，也不改变已创建订单。

## 验证范围

真实 stdio MCP 已完成普通单品的柜台自取切换、¥8.50报价、新进程恢复、重复调用及清空。加购、切换、清空各一次；清空后旧报价不可再用。原订单、钱包余额及账号偏好不变。

模拟环境验证了柜台自取订单创建与付款、取餐方式校验以及中断恢复；真实已有订单字段也做了只读对照。**没有新增柜台自取付款验收**，不能据此声称所有门店、卡券和取餐方式均已实际消费成功。原早餐卡取餐柜付款的证据保持独立。

# 直接短信登录

本地 CLI 已真实通过短信发送、验证码提交、返回手机号与会话绑定、钱包只读核验及新账号保存。验收使用已注册会员和本人已有的官方设备上下文，新账号默认禁止消费。本轮没有创建订单或付款。

官方 Mac App 的成功请求与脚本正文参数、加密、国家码、业务头、v4签名均匹配。早期只用新安装标识、缺少安全 SDK 设备字段的两次测试返回 `707053`；携带本人已接入的官方 `token` 与 `d` 后，纯脚本登录成功。此结果验证了这套设备上下文，不代表任意生成的设备标识都可用，也不单独证明两个字段中哪一个导致先前拒绝。

```sh
ezmcd account login personal --device-from existing-account
```

手机号和验证码只在本机终端输入，不回显，不作为命令参数，不提供给 MCP。仅测试用户本人控制、已注册麦当劳中国会员的手机号。每次交互最多发送一次短信，不创建订单或付款。

可以输入国内11位号码或带 `+86` 的号码；客户端统一将11位号码加密放入 `tel`，国家码单独放入 `regionCode: "86"`，与当前官方 App 的格式一致。

## 设备与协议

仍要求已支持的官方 App 二进制，默认路径和构建校验见[账号接入](onboarding.md)。手机号和验证码的加密材料从用户本机二进制读取，不随项目分发。

要求用户先拥有自己授权导入的官方设备上下文，通过 `--device-from` 明确选择；缺少 `deviceToken` 或安全 SDK 的 `riskDeviceId` 时，在发送短信之前停止。不会自行生成 SDK 结果或新安装标识来替代设备初始化，不会复制 v5 环境字段。旧开发版生成的独立安装标识不再用作登录上下文。

已有自己授权的官方设备上下文时，可显式使用：

```sh
ezmcd account login personal --device-from existing-account
```

这里只读取设备字段和客户端版本，登录请求不携带已有账号的 sid、会员标识或其他账号身份。

因此，当前仍不能承诺一台空白机器只填手机号即可接入。官方 SDK 的合法设备初始化与后续验证交接仍是依赖；短信登录也不能替代下单所需的运行字段。

## 成功与恢复

服务端必须成功返回匹配请求手机号的加密号码及新会话；随后查询钱包余额核验会话，成功后才保存账号。如果该会员已存在，会更新原有别名，保留消费策略和交易日志。不会复制旧会话的 v5 运行字段或延长其有效期。

发送或登录请求不会自动重试。输出的 `attempt_id` 可以用于恢复：

```sh
ezmcd account login personal --resume returned-attempt-id
```

恢复不发送新短信。只有已发送或发送结果未知且用户实际收到验证码时才允许提交一次验证码；已取得新会话、但余额查询暂时失败时，只重做只读核验和本地保存。

验证码最多保留在进程内，记录不保存明文或加密后的验证码。手机号仅保存脱敏展示和本地加密绑定值；限流使用本地加盐摘要。采样与会话记录仍受私有文件权限保护。完成后移除临时手机号绑定和重复会话副本。

官方额外安全验证、换绑或其他挑战会停止流程，不能把挑战当成短信发送或登录成功。当前不实现图形验证自动处理。单手机号本地发送间隔至少60秒，每小时最多3次；这些限制不替代官方限流。

失败记录仅保留 HTTP 状态、数字错误码、已知字段是否存在及去除数字和令牌的中文错误说明。不保存任意响应正文，不能仅凭错误码推断为安全挑战。错误返回非零退出码；恢复已拒绝的尝试只显示结果，不重新发送。

已核对的 `707053` 返回 `OFFICIAL_ACTION_REQUIRED`。应由用户核对官方 App 登录、按官方提示完成必要验证；本工具不把它当成验证码延迟，不自动更换设备或改号码格式重发。当前没有实现该限制的官方验证交接流程。

登录返回刷新令牌时，可通过 `account refresh` 或 MCP 的 `account_refresh` 维护会话，详见[会话维护](session-maintenance.md)。这不等于已具备下单运行字段。短信成功后的纯脚本购买仍遵守现有运行字段、报价、消费策略和防重复约束。

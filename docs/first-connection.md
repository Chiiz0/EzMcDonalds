# 从本人官方 App 首次接入

`sampling-connect` 面向已注册、已在支持的 Mac 官方 App 登录的会员，让项目自行采集一条签名余额请求并接入账号。不要求先整理HAR或复制请求；手机号、验证码和登录操作仍留在官方App。它没有实现空白设备的SDK初始化，也不是直接短信登录入口。

## 准备

- 使用[账号接入文档](onboarding.md)列出的官方App版本和二进制；其他版本会停止。
- 本机采样需要 Python 3.12+ 和可选依赖。核心CLI/MCP仍支持 Python 3.11。
- 先在 App 登录自己的会员，确认麦钱包正常显示。关闭其他使用麦当劳账号的窗口，避免采到另一个会话。项目保存采样中第一个签名和余额校验通过的会话，不凭输入的别名推断手机号归属。
- 使用原数据目录；已有会员请维护原账号，不要用新目录绕过购买日志。别名或同一会员已经存在时，首次接入会拒绝覆盖。

```sh
.venv/bin/python -m pip install -e '.[sampling]'
.venv/bin/ezmcd sampling-cert prepare
.venv/bin/ezmcd sampling-cert install
.venv/bin/ezmcd sampling-connect personal --manage-app
```

所有命令使用同一数据目录；自定义时把 `--data-dir /absolute/path/data` 放在子命令之前。证书首次安装由本人完成macOS系统授权，仅限当前用户的 `api.mcd.cn` SSL信任；每轮采样结束恢复代理，证书保留到本人撤销。[证书说明](sampling-certificate.md)。项目不会自动安装证书。

## 一次操作

1. 阅读本机终端准备提示，按回车开始；输入 `q` 可在代理启用前取消。不能通过管道自动确认。
2. `--manage-app` 核验并退出官方App，保护器通过发送前阻断自检、代理生效后才重新打开。省略此参数时由本人按提示退出和打开App。
3. 进入麦钱包余额页即可。不要操作购物车、登录或付款；无需提交测试订单。
4. 余额请求的官方签名与成功响应校验通过后立即收尾。App及本轮启动器结束后才恢复代理；退出失败会提示手动处理，期间保持阻断。
5. 代理恢复后再查询一次实时余额，成功才保存新账号。最终 `account_created=true` 表示完成接入；仅看到 `balance_saved=true` 不表示已接入。

窗口最多120秒，可用 `--seconds 30` 缩短。`--network-service` 指定本机当前联网服务，默认Wi-Fi；已有活动代理时停止。需要时可显式指定 `--binary` 和 `--mitmdump` 路径。

首次接入期间只放行限定官方GET。登录、短信、刷新、购物车、订单和付款写入全部阻断。如果App需要重新登录或刷新才能显示余额，先等本轮退出并恢复代理，再在官方入口登录后重新采样；不手工补字段，不在保护窗口里反复重试。

## 接入后

```sh
.venv/bin/ezmcd account check personal
.venv/bin/ezmcd mcp-config
```

凭据只保存于本机私有文件，不经MCP或聊天传递。首次账号消费默认关闭，没有下单运行字段；Agent可以核验会话、找店、选择商品和报价。需要下单时，先按[无订单运行字段采样](guarded-capture.md)取得本人新证据，再由用户设置明确消费策略。首次接入本身既不授予消费权限，也不启动定时购买。

## 失败与恢复

完成采样但实时余额核验或保存失败时，命令返回非零状态，保留采样目录、`import_error` 和 `resume_command`。后者只重新核验和导入，不启动App或代理。也可手工执行：

```sh
.venv/bin/ezmcd sampling-import personal /absolute/path/data/captures/采样编号 --connect
```

同一成功目录重复导入只查询余额，不改写凭据、策略或购买记录。别名、会员、签名、清理状态或回执不符时停止；不能覆盖已有账号、恢复已撤销凭据或替换之后更新的会话。已存在的会员使用[会话维护](session-maintenance.md)，不改名重接。未取得完整余额样本时先完成清理，再按原因开始新窗口。

采样目录含私有会话字段，权限0700/0600，不要上传仓库或发到聊天。只保留必要请求头和脱敏审计，不保存余额金额正文、Cookie、订单正文或原始代理日志。

## 当前验证范围

隔离测试覆盖首次身份绑定、签名失败、禁止刷新与金融请求、余额到达即退出、代理恢复、重复或失败导入、旧会员拒绝覆盖及本机终端交互。真实终端开始前取消已验证。

另用既有本人签名余额样本离线回放新保护器，再真实执行余额GET核验、隔离账号首次导入、重复导入及新MCP进程会话检查，共三次GET；原账号、偏好和所有日志表不变，隔离账号凭据已撤销。该既有样本证据不包含新的App流量或代理启停，与下面的后续实机验收分开记录。

随后在一个已有会员上运行新的公开 `sampling-connect --manage-app`，使用隔离目录和本机原有受限证书。用户只进入麦钱包；真实采到新的原生签名余额请求，公开命令自动开关App、等待启动器结束并恢复代理，再完成首次导入和重复只读核验。账号默认禁止消费、无运行字段，原账号/偏好/全部日志表/官方订单/钱包余额保持不变；测试账号凭据已撤销，证书保留。辅助脚本只复用原证书管理器、记录事件并做前后核验，没有替代公开App控制流程。

这次证明一次已有会员的首次接入流程，不证明设备字段独立初始化、跨日自动续期或无人值守。下单运行字段仍需另行更新。

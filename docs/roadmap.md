# 产品目标与验收路线

用户在自己的设备授权自己的手机号账号，将可查询、可报价、可购买、可追踪的能力交给个人Agent。账号、门店、餐品、优惠与预算由用户决定，核心不预设杭州、早餐、套餐或日期。

## v0.1 alpha：项目化

已实现包、CLI、HAR/样本本地接入与撤销、多账号身份隔离、递归菜单、套餐详情和标准组件选择、通用购物车校验、消费策略、防重复日志、钱包适配、16个MCP工具及离线演示。真实证据包含已完成的一笔原型早餐付款，新适配器验证了当前账号的只读访问。它是可开发和接入的alpha，不是大众用户一键接入成品。

## v0.2：自助授权与会话维护

- 本地账号界面完成手机号、验证码和官方验证，不把凭据交给聊天。
- 核对短信登录、设备初始化及刷新完整流程；发现URL不等于验证API。
- 验收重新登录、账号切换、退出、会话和设备字段过期。
- 至少两个由各自所有者授权的真实账号分别查询，凭据不交叉，更新凭据不丢失日志。

## v0.3：完整商品选择

- 店名/位置搜索、门店和取餐时间选择。
- 已接入实时商品详情及标准套餐轮次选择；继续验收加购、扩展饮品定制、加价项、份数和特殊要求。
- 早餐卡、其他权益卡、单品券、整单优惠适用与互斥。
- 验收跨店单品、多品、多份、套餐换购及无优惠单；缺货、停售、权益过期、涨价或跨餐段需停止并给出原因。

## v0.4：真实消费矩阵

- 每个真实订单绑定具体授权、金额上限和取餐安排，协议测试默认只读或模拟。
- 验收已建未付、预支付挑战、消费超时、扣款后回执丢失、取消后历史PAID。
- 确认账号、订单、钱包交易与取餐码关联，补充退款到账证据。
- 一笔成功早餐不能替代这组验收。

## v1.0：日常可用

- 一次性授权或持续策略，缺货/涨价/验证时通知。
- 稳定凭据生命周期、跨日预算和购买意图管理，Agent重启/重发不重复消费。
- 常见MCP客户端安装、升级、诊断及卸载流程。
- 如需托管远程服务，单独设计部署模式；个人本地使用不必先搭服务器。

# 产品目标与验收路线

用户在自己的设备授权自己的手机号账号，将可查询、可报价、可购买、可追踪的能力交给个人Agent。账号、门店、餐品、优惠与预算由用户决定，核心不预设杭州、早餐、套餐或日期。

## v0.1 alpha：项目化

已实现包、CLI、HAR/样本本地接入与撤销、多账号身份隔离、递归菜单、门店时段券查询、套餐详情和标准组件选择、通用购物车校验、消费策略、防重复日志、钱包适配、38个MCP工具及离线演示。公开核心已通过 MCP 完成一笔早餐卡自取订单与麦钱包付款，重启重复调用未新增消费。它是可开发和接入的alpha，不是大众用户一键接入成品。

## v0.4：真实消费矩阵

- 公开核心的单店早餐组合已完成真实消费及重启去重验收；首次状态同步延迟后，只读核对确认成功。
- 已提供按账号、取餐日期和状态找回本地订单的入口；换聊天后先找原尝试，再实时核对，不需要重新提交购买。
- 默认选餐入口会先查同账号、门店和取餐时间的本地购买，已有记录时直接交回原尝试；明确日期可恢复过去餐次，登录失效不妨碍离线找回。正常下一餐仍根据未来偏好及实时预约范围选餐，真实账号日志的新进程恢复已验证。
- 每个真实订单绑定具体授权、金额上限和取餐安排，协议测试默认只读或模拟。
- 验收已建未付、预支付挑战、消费超时、扣款后回执丢失、取消后历史PAID。
- 官方订单分页、详情与收银台只读查询已通过真实验证；可以查看未记入本地日志的订单。回执丢失后的字段比对由模拟测试覆盖，仅用于核对候选，不自动关联未知请求或付款。
- 确认账号、订单、钱包交易与取餐码关联，补充退款到账证据。
- 一笔成功早餐不能替代这组验收。

## v1.0：日常可用

- 一次性授权或持续策略，缺货/涨价/验证时通知。
- 已提供跨日过时意图的本地列表与明确结束，不再因旧取餐时间无法查询而一直阻塞新餐；隔离测试覆盖原键不重发、新餐模拟购买和未知购买仍被保护。跨日凭据有效性尚未由此证明。
- 稳定凭据生命周期、跨日预算和购买意图管理，Agent重启/重发不重复消费。
- 常见MCP客户端安装、升级、诊断及卸载流程。
- 如需托管远程服务，单独设计部署模式；个人本地使用不必先搭服务器。

# 产品目标与验收路线

用户在自己的设备授权自己的手机号账号，将可查询、可报价、可购买、可追踪的能力交给个人Agent。账号、门店、餐品、优惠与预算由用户决定，核心不预设杭州、早餐、套餐或日期。

## v0.1 alpha：项目化

已实现包、CLI、HAR/样本本地接入与撤销、多账号身份隔离、递归菜单、门店时段券查询、套餐详情和标准组件选择、通用购物车校验、消费策略、防重复日志、钱包适配、28个MCP工具及离线演示。公开核心已通过 MCP 完成一笔早餐卡自取订单与麦钱包付款，重启重复调用未新增消费。它是可开发和接入的alpha，不是大众用户一键接入成品。

## v0.2：已有账号维护优先

- 当前聚焦已经接入的用户，暂缓空白设备首次接入。设备字段来源和独立实现范围见[设备上下文](device-context.md)。
- 本地短信登录和按需会话刷新已通过真实验收；刷新恢复不重发，保留身份、策略与购买日志。
- 验收重新登录、账号切换、退出、会话和设备字段过期。
- 两个授权账号已分别完成接入与只读核验；继续验收跨日维护、设备字段过期和跨账号购买。

## v0.3：完整商品选择

- 已实现城市/店名搜索、明确坐标附近查询、可预约时段标准化；原门店及周边真实核验通过。
- 已实现偏好保存、实时选餐方案和账号诊断；继续简化凭据更新，避免日常依赖手工抓包。
- 已提供同会话运行样本独立更新，以及同设备上下文的显式 v5 GET 核验复用；随后一笔新会话订单 POST 和付款已通过，跨日持久性仍待验证。
- 已提供历史运行样本的只读诊断，不延长样本期限；本机隐蔽粘贴请求头可直接导入。无订单采样核心已完成官方 App 实机验证，新增本机 `sampling-capture` 命令与代理恢复；新签名只读核验通过，订单与余额未变化。
- 已增加本机剪贴板/私有文本导入单条请求，不再要求整理 HAR；文件 CLI 入口以现有授权会话完成真实只读核验。完整官方 App 请求阻断与代理恢复已验证；官方剪贴板实操仍待验收。
- 已接入规格列表、免费保留/去除及单选配料配置，新增修改路径尚待真实加购验证。
- 偏好可按实时配料名称表达保留/去除及冰量等单选；缺项、歧义与实时约束冲突会停止。可选套餐轮次可明确留空。
- 已接入实时商品详情及标准套餐轮次选择；原组合加购和早餐卡结算已真实通过；继续验收更多饮品定制、加价项、份数和特殊要求。
- 门店时段券与对应商品已真实只读核验；普通单品券构造及指定券名称偏好已实现，真实加购结算待验收。继续适配特殊券、整单优惠及其互斥关系。
- 验收跨店单品、多品、多份、套餐换购及无优惠单；缺货、停售、权益过期、涨价或跨餐段需停止并给出原因。

## v0.4：真实消费矩阵

- 公开核心的单店早餐组合已完成真实消费及重启去重验收；首次状态同步延迟后，只读核对确认成功。
- 已提供按账号、取餐日期和状态找回本地订单的入口；换聊天后先找原尝试，再实时核对，不需要重新提交购买。
- 每个真实订单绑定具体授权、金额上限和取餐安排，协议测试默认只读或模拟。
- 验收已建未付、预支付挑战、消费超时、扣款后回执丢失、取消后历史PAID。
- 确认账号、订单、钱包交易与取餐码关联，补充退款到账证据。
- 一笔成功早餐不能替代这组验收。

## v1.0：日常可用

- 一次性授权或持续策略，缺货/涨价/验证时通知。
- 稳定凭据生命周期、跨日预算和购买意图管理，Agent重启/重发不重复消费。
- 常见MCP客户端安装、升级、诊断及卸载流程。
- 如需托管远程服务，单独设计部署模式；个人本地使用不必先搭服务器。

# 显式限期复用本人运行字段

已有账号可以选择在有限期限内继续使用原先取得的官方运行字段，减少重复采样。**这不是取得新字段；许可中的只读核验也不保证后续下单一定成功。** a40 使用约72小时的本人样本完成了实时查单、CLI授权与撤销、新MCP进程状态核验；没有发送订单或付款请求。

默认上限仍是24小时。需要复用时，由用户在本机明确选择原样本的最大年龄：

```sh
ezmcd account runtime-use personal --max-age-hours 96
ezmcd account check personal

# 随时撤销，不联网；原样本和购买日志保留
ezmcd account runtime-use personal --disable
```

数值可选25至336小时，**从原采样时刻计算**，不是从授权时刻重新计时。例如72小时前的样本选择96小时，只剩约24小时可用。a45将试验性上限由7天扩展到14天；这不是官方承诺的有效期。升级不会自动延长已有许可，原先选择96或168小时的账号仍按原期限到期。重复执行同一授权会再查询一次，但不改原采样日期、到期时间或消费额度；已超过所选期限时拒绝。缺少样本时不能使用此命令。

如果用户明确选择14天，在本机执行：

```sh
ezmcd account runtime-use personal --max-age-hours 336
```

原样本已使用10天时，这条命令最多再允许约4天；不会从执行命令时再算14天。到期、只读核验失败或账号绑定变化都会停止使用。约10天样本已有一次真实消费证据，但不能据此保证所有较老字段都可用，也不能把这条命令成功当作下单已经通过。

## 下单前的核验

授权绑定当前账号、客户端路径、完整登录与设备资料及原样本。命令先用当前会话和新签名查询订单列表第一页，成功后才保存本地许可。服务器拒绝或返回无法识别的结构时不保存。授权不会把账号从“消费关闭”改为可购买，也不更改默认门店、偏好或购买日志。

个人Agent不能通过MCP开启、延长或撤销该许可，只能查看 `account_check` / `account_runtime_check` 中的 `runtime_use` 状态。用户已设置消费策略且准备购买时，项目仍按原规则核对实时购物车、报价、预算及已有订单；使用超过24小时的字段还必须再执行一次签名查单。

这次即时核验只供当前进程中的当前订单正文使用，一次有效，最多60秒。换正文、换凭据、撤销或修改许可、超时、重启均不能沿用。初次授权和普通 `account_runtime_check` 的成功结果不能替代下单前核验。响应拒绝时停止，不自动刷新、重发订单或扣款；原有防重复日志仍适用。

重新登录、导入会话或成功刷新后许可不继承；换设备字段、客户端或运行样本也会使原绑定失效。此时应检查当前账号，按需要重新取得本人资料或显式授权，不能通过修改采样日期恢复。许可到期后恢复默认24小时规则。

## 已验证和未验证

`account_runtime_check` 的 `order_post_acceptance_verified=false` 表示这次只读检查本身不验证订单POST。具体购买是否成功仍查看对应的 `order_status` 与购买记录，不能把项目的一次实机成功推广到所有账号。

- 真实旧样本的只读签名查询通过；在隔离账号副本中，公开CLI授权、重复授权不延长、撤销，以及新MCP进程展示均通过。原账号、策略、偏好、全部日志和网络设置未变。
- a40隔离测试中的订单签名只在本机生成并重建核对，没有发送出去。正文、时限、凭据和许可绑定、单次使用、消费仍关闭、核验失败不建立购买尝试，均有隔离测试。
- a46记录了一笔约10天本人样本的实际消费：明确授权后重新核对同价报价、查重与即时签名，订单POST、预支付、麦钱包扣款各一次，¥12.60余额差额与订单及收银台一致；新进程重复原购买键只查询同一单。原采样日期与复用到期时间不变，消费权限已关闭。其他样本年龄、设备、门店或连续多日使用仍未由这一单证明。
- 此功能不生成设备标识，不绕过官方验证，不设置定时购买；缺少原样本的首次接入仍需[本人官方凭据](credentials.md)。
